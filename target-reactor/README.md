# 定点表情回应

LiteLoaderQQNT 独立插件，版本 `0.1.0`，依赖已安装的 `ipc_interceptor`。为指定群内指定成员的新消息添加一个指定的 QQ 表情回应，不发送聊天文字或图片消息。

## 使用

1. 安装后完全退出 QQ，再启动。
2. 在 QQ 设置 → LiteLoader →“定点表情回应”中填写群号和成员 QQ 号。成员也可使用 `u_` 开头的 QQ UID；近期收到消息的群和成员可从输入框候选项中选择。
3. 选择表情，点击“添加规则”。默认选中截图同款 😝“吐舌”，也可搜索和选择其它本地表情。
4. 打开顶部“启用自动回应”总开关。初次安装默认关闭，不配置目标，不自动发送回应。

支持多条规则；同一群内同一成员只保留一条规则，可编辑、暂停、恢复和删除。规则按当前 QQ 登录账号保存，不使用昵称来识别人，以免同名误匹配。回应属于 QQ 原生表情回应，群内成员可以看到。

仅处理启用后实时收到、时间有效的新群消息，忽略历史拉取、离线补发、系统提示及自己的消息。同一条消息的多窗口通知、重复通知和重启重放不会重复回应。修改规则会清空等待队列并重新确定启用边界。

回应串行发出，间隔至少 800 毫秒；队列上限 100 条，超过一分钟的等待消息不再处理。关闭总开关立即清空等待队列；已经发出的回应不会自动撤销。QQ 超时、错误或没有明确成功结果时，当前规则暂停，不自动重试同一条消息。可在规则下方和“最近执行”中查看原因，处理后点击“恢复规则”。

## 数据和实现

数据位于 LiteLoader 用户数据目录的 `target_reactor/<账号 UID>/`：`rules.json` 保存配置，`processed.json` 保存最近 5000 条已处理消息的哈希。插件不保存聊天正文。最近群和成员候选项、执行记录仅在内存保留。

- `lib/rules.js`：身份验证、配置验证、回应请求及结果解释。
- `lib/preferences.js`：账号配置和去重记录的原子存储。
- `lib/native_transport.js`：经真实 QQ 渲染进程发送固定的 `setMsgEmojiLikes` 请求。
- `lib/reaction_engine.js`：新消息匹配、去重、串行队列及暂停状态。
- `lib/emoji_catalog.js`：读取当前 QQ 安装和用户数据中的可见表情目录，不访问网络。
- `renderer.mjs`、`ui/`：设置面板。

接口约定参考已安装的 QQ 及 IPC 事件拦截器，以及公开项目 [QQNT-Toolbox](https://github.com/MeiYongAI/QQNT-Toolbox) 的原生调用参数；插件业务代码为独立实现，没有复制该项目源码。

## 验证

工作区执行：`node --test tests/target_reactor.test.cjs`、`node tests/target_reactor_ui.cjs`。覆盖严格目标匹配、原生参数、重复通知与重启去重、历史排除、间隔、关闭队列、账号切换、错误暂停、文件异常、预加载权限以及完整主进程链路；界面测试使用模拟接口验证设置流程和布局。

开发时未向真实群添加测试回应。真实 QQ 场景由用户在重启、配置并启用规则后验证。
