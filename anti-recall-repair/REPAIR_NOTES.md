# 后台图片防撤回修复

本地版本：`0.3.2-local.2`，基于 xh321 的 MIT 许可防撤回插件 `0.3.0`。

## 撤回消息查看

入口为 QQ 设置中的“防撤回”插件页 →“查看撤回消息”。独立窗口左侧按会话分组，右侧显示发送者、原发送时间及已保留的文字、图片和附件信息。搜索同时匹配会话名、群号、发送者和消息正文，历史记录每次加载 50 条。数据来自已有的撤回数据库和本次运行的撤回记录，不依赖轻量工具箱的数据文件。

单击图片可以放大；双击任意消息（包括图片）会向 QQ 原生 `jumpNewAio` 请求打开原会话，并通过原消息 ID 定位。聚焦消息后按 Enter 也可定位。界面只提示已发出定位请求，不把请求发出当作定位成功；群已退出或本地会话记录被清理时，QQ 可能无法定位。

旧版记录保持可读，更新不迁移或重写已有数据库。消息内容按纯文本渲染，图片通过主进程登记的令牌读取，页面不能指定任意本地文件路径。未保存的图片会显示明确提示。

左右两栏限制在窗口高度内，会话列表与消息列表各自滚动，顶部搜索和底部操作栏固定显示。滚动条保留独立轨道并提高对比度；长会话列表、长消息和缩小窗口不会再把内容撑到窗口外。相关回归为 `node tests/anti_recall_viewer_scroll.cjs`，使用真实滚轮和原生滚动条拖动检查三种窗口尺寸。

## 图片保护

旧版只缓存消息对象，在收到撤回或打开历史时才下载图片；后台没有加载过的图片可能已经失去服务器下载权限。旧下载器还把未限定的 `statSync` 异常忽略，没有验证 HTTP 状态码、图片格式或下载完整性。

现在收到图片就启动后台下载，优先使用 QQ 登录会话的 `downloadRichMedia` 接口。失败时仅尝试消息中已有凭证的腾讯图片地址和旧版 MD5 地址，不访问第三方 rkey 服务。下载有并发、队列、大小和超时限制；通过图片格式和原消息 MD5 校验后才写文件。

图片保存在插件数据目录 `anti_recall/image_cache`。未撤回图片的暂存上限为 512 MiB，保留两小时；单张上限 32 MiB，同时最多下载三张。开启原有“存入数据库”选项后，已撤回图片另行保留，随“清空已储存的撤回消息”清理。账号路径、会话、消息与元素共同区分缓存。缓存不保存消息文本或下载地址。

撤回后恢复原图和缩略图的本地路径，再更新图片消息；重新打开历史和重启也优先读取已保存的图片。升级不会修改现有配置或数据库。重启 QQ 后生效。

离线验证：`node --test tests/anti_recall_images.test.cjs`，包含后台预取、撤回与下载竞态、去重限流、持久化、错误文件替换、HTTP 错误及主进程集成场景。真实 QQ 的原生下载接口与图片显示仍需用户验证。测试不发送消息、不调用真实 QQ 或网络。

查看器验证：`node --test tests/anti_recall_viewer.test.cjs` 和 `node tests/anti_recall_viewer_ui.cjs`。覆盖旧数据库结构、搜索与分页、精确消息 ID、跳转参数转义、窗口接口权限、图片预览与双击定位的区分、缺失媒体和数据库错误。

在修复生效前已撤回、且本地从未保存的图片，如果服务器链接也已失效，无法凭消息元数据重建图片。

参考上游：[LiteLoaderQQNT-Anti-Recall](https://github.com/xh321/LiteLoaderQQNT-Anti-Recall)。QQ 原生下载接口参数参考公开项目 [QQNT-Toolbox](https://github.com/MeiYongAI/QQNT-Toolbox)；修复模块为独立实现，未复制其源代码。
