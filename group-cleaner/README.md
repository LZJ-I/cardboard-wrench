# 群清理助手 0.1.4

为本机 Windows QQNT / LiteLoaderQQNT 1.4.1 制作的群管理插件。运行时只依赖已安装的 `ipc_interceptor`，无需 npm 安装或额外服务。

## 使用

1. 完全退出 QQ 后重新启动。
2. 打开 **QQ 设置 → 群清理助手**，或者在 QQ 消息主窗口按 **Ctrl + Shift + G**。
3. 点击“刷新群列表”。可按群名、群备注、群号搜索，按名称或人数排序。
   点击群名可打开对应群聊，搜索、勾选和滚动位置保留。快捷面板会收起，用同一快捷键可回到原位置。
   QQ 9.9.37-54395 内置了已成功验证的默认退群适配，首次使用无需校准；已有同版本手动校准时优先沿用。接口调用失败后停止队列并提示手动校准，重启不会继续尝试已失效的适配。需要校准时，点“开始校准退群”，再通过 QQ 原生按钮退出一个自己确定要退出的群。校准只观察这次操作，不额外退群。
4. 重要群可点击“保留”。保留名单按 QQ 账号单独存储。
5. 点击单行“退群”，或者勾选后点击“退出所选群”。QQ 会弹出一份包含群名、群号的最终确认名单；默认选中“取消”。
6. 批量任务逐个执行，可停止后续操作。成功退出的行移除，搜索条件与列表位置保留。一次最多选择 200 个群。

群主的群自动排除，不包含解散群的功能。不能确认身份的群暂时不可选。

退群优先使用同版本手动校准，其次使用内置的已验证适配，由真实 QQ 渲染进程发送。接口失效或无当前版本适配时再提示校准。模板中的群号使用占位符；不保存群名、账号凭证或聊天内容。插件不额外调用清理聊天记录的接口；原生参数包含清理设置时会在最终确认中明确说明。

0.1.1 针对 0.1.0 退群返回错误码 4 的反馈调整了接口调用。实际退群效果仍需用户验证；返回失败会直接显示在面板顶部，并展开执行记录。

0.1.2 针对兼容入口仍返回错误码 5 的反馈增加原生退群校准，停止使用未验证的固定退群参数，并将原生请求改为经过真实渲染进程 IPC 发送。仍需用户校准并验证真实退群效果。

0.1.3 修复跨 V8 上下文普通对象、undefined 和 BigInt 参数的无损校准；修复空任务通知被误当成切换账号而清空群列表。校准失败会保存仅含字段类型、布尔设置和结果码的 `native-quit-diagnostic.json`，不记录群号、群名、聊天内容或认证字段值。

## 结果与停止

- 返回成功后还会刷新群列表，确认对应群已经消失才显示“已退出”。
- 接口超时、返回失败或群列表未能确认时，停止剩余队列并显示待核实信息。不会自动重发退群请求。
- “停止后续操作”不能撤销已经发出的请求。关闭发起任务的 QQ 窗口或切换账号，会在当前请求结束后停止后续操作。
- 关闭快捷面板不等于退出任务。需要停止时请点击“停止后续操作”。
- 执行任务和选择名单只存在内存中，重启 QQ 不会自动继续。

## 数据位置

`LiteLoaderQQNT 数据目录/data/group_cleaner/<账号 UID>.json` 只保存保留群号。不保存聊天内容、不上传群列表、不提供网络服务。

## 兼容与排查

本机开发目标是 QQNT **9.9.37-54395**、LiteLoaderQQNT **1.4.1**、IPC 前置插件 **1.2.0**。QQ 内部接口不是稳定公开 API，更新 QQ 后可能需要适配。

- 没有面板入口：在 LiteLoader 插件列表检查“群清理助手”和“IPC 事件拦截器”是否启用，并完全重启 QQ。
- 未收到登录信息：在 QQ 登录完成后重试；插件应随 QQ 冷启动加载。
- 群列表读取失败：先打开 QQ 联系人中的群聊列表，再回面板刷新。错误信息会直接显示在面板，不会执行退群。
- 操作待核实：先刷新群列表确认实际成员状态，再决定是否重新选择。不要重复点击或删除保存保留名单的文件。
- 卸载：在 LiteLoader 中停用插件并重启；移除 `plugins/group_cleaner` 文件夹即可，保留名单单独存储。

## 验证范围

开发阶段进行离线模拟测试和语法检查，测试中不会连接真实 QQ，也不会执行任何真实退群。真实账号、群列表和退群效果由用户重启后验证。

建议先验证读取列表、搜索、保留、取消确认，再用一个自己决定退出的测试群验证单群退出；之后再尝试小批量。
